# Code and test review, September 10, 2026

This records the initial audit and dependency-update phase, before the subsequent feature implementation. Its 185-test counts, script benchmark, and final coordination limitations describe that earlier snapshot. See [the feature guide](cache-features.md) for the new behavior and its consistency limits.

## Changes

- HTTP cache hits retain status, content type, quoted text, JSON-looking text, and binary bodies. The middleware caches GET only, preventing cached GET responses from suppressing POST handlers. Fastify streams bypass serialization.
- Fastify uses request-local hit state instead of the optional `X-Cache` header. Cache hits no longer rewrite data or extend TTL when headers are disabled. It computes the canonical key once and continues serving the handler if key generation fails.
- Query normalization preserves own `__proto__` properties instead of silently dropping them from cache keys. Manual clears honor custom query exclusions.
- Temporary clear helpers preserve unrelated shared LRU entries, avoid local broadcast subscriptions, and leave caller-owned custom backends open.
- Standalone LRU metadata survives payload expiry for `metaTTL`. Oversized replacement writes remove the older cached payload. Initial and changed-content TTLs respect `maxTTL`.
- LRU refresh acquisition uses the dependency's atomic `setIfAbsent`, bypasses local L1 for coordination reads, and retries when an owner disappears between a failed claim and observation. Lock tokens use UUIDs.
- L1 invalidation drains writes shared by cache instances using the same Redis client. Invalidation generations prevent delayed Redis reads from rehydrating cleared data. Already-started hydrations finish before deletion. Malformed pub/sub message shapes are ignored.
- Lua reads use `HMGET` for the four metadata fields used by the algorithm, eliminating hash-wide scans and Lua dictionary allocation.

## Test changes and evidence

The new regressions first reproduced failures including 16 simultaneous refresh winners, HTTP method collisions, lost status/content type, stale oversized replacements, lost adaptive history, and stale L1 resurrection after clear. Controlled async gates exercise interleavings, using real LRU operations and a Redis transport double. The existing Redis suites run actual Lua scripts in Testcontainers.

Removed a duplicate invalid-duration test. Replaced ineffective shared-client/clear tests, strengthened undefined round-trip checks to require a hit, and replaced TTL log assertions with stored Redis metadata. HTTP tests now establish hits and handler counts. The test that expected quoted text to lose its quotes now requires the original response. Tests that previously only invoked Fastify now assert response and cache behavior. A suite-wide assertion guard prevents assertion-free Vitest tests.

Validation: 185 tests pass across 11 files. Coverage remains 100% for statements, branches, functions, and lines, with thresholds unchanged. Lint and TypeScript checks pass. CJS, ESM, and declarations build successfully. The full suite also passes under Node 22.19.0, and both built module formats pass binary round-trip and concurrent-refresh smoke checks.

## Performance measurement

An isolated Redis container ran six alternating batches of 10,000 calls for each fetch script. Both used the same payload and four-field metadata hash. Redis `EVALSHA` CPU microseconds per call:

| Version  | Samples                            | Median |
| -------- | ---------------------------------- | ------ |
| Original | 3.56, 3.32, 3.33, 3.58, 4.18, 3.75 | 3.57   |
| Updated  | 2.50, 2.74, 2.41, 2.43, 4.01, 3.17 | 2.62   |

The median is about 27% lower. This measures script CPU in this environment, not application throughput. The Fastify regression also verifies that three cache hits with headers disabled produce zero backend writes instead of three.

## Remaining coordination limits

Standalone LRU release still reads ownership and deletes in separate operations. A delayed releaser can delete a newer forced or expired-lock replacement. The current optional dependency provides no public atomic compare-and-delete API. Redis-backed locking uses atomic Lua and is the appropriate backend for strict coordination. Fixing standalone release fully requires an upstream atomic operation or a separate coordination protocol; the new atomic acquisition test does not claim to solve release races.

Pending-write draining is scoped to instances sharing a Redis client in this process. Cross-process invalidation relies on pub/sub and remains eventually consistent; it is not a transaction fencing every write in other processes. These limitations are not covered up by passing coverage percentages.
